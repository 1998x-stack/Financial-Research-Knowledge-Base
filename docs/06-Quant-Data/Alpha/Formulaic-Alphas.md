# 公式型Alpha：数据语义、信号构建、组合与可复现检验

[← 量化与数据](../README.md) · [Yahoo数据工程](../Data-Engineering/Yahoo-Finance-Pipeline.md) · [来源台账](../../10-Sources/Source-Ledger.md)

> **研究状态**：方法论与论文解读，尚无本仓库独立回测结果。**更新**：2026-09-21。研究起点为本项目附件：Zura Kakushadze, *101 Formulaic Alphas*（2015），尤其第2—3节、附录A.2/A.3及表1—5；下文只做原创总结，不复刻附录的整套受版权保护公式。

## 1. 理解论文的样本与不能外推的结论

论文中的‘alpha’是用于预测金融工具未来变化的可执行表达式，不等于标准业绩归因中的截距alpha。作者描述的101个信号主要使用价格、成交量、VWAP，少量使用市值和行业分类；既有均值回归也有动量及其组合。论文披露的部分实证样本为2010-01-04至2013-12-31，并依赖作者可访问的专有交易数据；其表1业绩明确不包含交易成本/市场冲击。因而无法将论文中的Sharpe、平均持有期或相关性直接视作今天A股、港股可达到的表现。

## 2. 明确数据和运算符的时点语义

每一条数据必须带 `valid_time（经济上发生时刻）`、`available_time（首次可用时刻）`、`ingested_time（本地记录时刻）`；市场日线的open/high/low/close在不同交易时刻可用性不同，日终VWAP不可能用于同一交易日开盘成交。`rank`通常指同一观察截面的横截面排序，`ts_rank`是在同一资产历史窗口内排序，两者不可互换；行业中性化按当时有效的分组计算。`delay(x,d)`针对观察值滞后，不自动保证信号到成交之间有足够时间；必须显式记录`signal_timestamp`和`execution_timestamp`。

**重要边界**：论文将少量信号标为delay-0，假设在使用当日数据时接近同日收盘交易；现实中必须证明该时刻的输入已产生且可处理，并考虑收盘撮合/竞价约束。不能用完整日线最高、最低、收盘或整日VWAP生成同日收盘前的‘可预见’信号，再用该收盘价假设无滑点执行。

## 3. 从公式到可投资组合的五层处理

原始信号 `s(i,t)` → 数据质量/异常值处理 → 行业、市值等风险暴露检验 → 组合优化与权重 `w(i,t)` → 订单执行与持仓现金流。横截面排序可能因缺失值、停牌或股票池变化而改变；行业去均值后不等于全部风险中性。组合约束至少包含净/毛敞口、行业上限、单一资产上限、日均成交额参与率、换手与融资限制，并记录是否允许做空与相应市场制度。

一个研究用净收益关系：`净收益_t = Σ_i w_(i,t−1) × r_(i,t) − 交易费用_t − 滑点_t − 借券/融资成本_t`。必须在交易时点确认权重，否则把t日收盘信号乘t日收盘至收盘收益就是时间错配。A股涨跌停、停牌、T+1卖出约束和港股交易制度应进入市场特定执行模拟；无法成交的订单不能以理论收盘价自动成交。

## 4. 验证流程与防止过拟合

按时间先后切分研究、调参和最终锁定的样本外区间；滚动或扩展窗口重新训练，避免随机抽样打乱时间依赖。记录所有试验数量、筛选标准、参数选择日期及数据修订版本；同时报告多个相关信号组合后是否仍有独立贡献。避免以今天的成分股回测十年前历史，纳入退市股、当时行业分类及可交易限制。统计测试关注因子IC/RankIC及其稳定性、长短分组、持有期收益、收益分布、换手、容量、成本后的净收益和极端情景，不只看年化收益或单个Sharpe。

## 5. 实证指标与论文口径

定义年化Sharpe（以日频近似）`SR = sqrt(252) × mean(daily_excess_return)/std(daily_excess_return)`，前提是样本频率、无风险收益和标准差估计口径明确。横截面相关性低不保证极端市场尾部独立；换手越高不必然收益越差，但更可能要求成本、容量与执行时点检验。论文对‘收益与波动率相关、单独的换手对部分相关结构解释有限’的实证讨论仅成立于该论文具体样本和建模设定，不是所有市场普适定律。

## 6. 复现记录与自动化质量门禁

最小实验元数据：`experiment_id / formula_ref / code_commit / universe_version / calendar / data_snapshot / signal_time / execution_rule / fee_model / slippage_model / borrow_rule / train_period / test_period / result_hash`。单元测试应覆盖未来函数、rank并列值、NaN、行业空组、拆分送股复权、特殊交易日、停牌与涨跌停；集成测试覆盖因子→订单→成交→持仓→NAV的逐笔对账。发现结果异常优先排查数据泄漏和不可能成交，而不是立即调整公式提高业绩。
